# RustDesk SX 2.1.0 — independent version numbering

Release tag `v2.1.0`; application and Debian package version `2.1.0`. Starting
with this release, SX no longer uses `1.5.0+sx.DATE` as its product version.
Upstream provenance remains RustDesk1.5.0; old releases and dated validation
records retain their original versions. The development branch is unchanged.

## Scope

This is a version/packaging update over the previously installed and tested
unattended release. No capture, encoder, input, clipboard, authentication, wake
policy or remote protocol implementation was changed. Historical peer-version
capability thresholds remain intact; they are not product-version metadata.

Cargo.toml is the Rust/runtime version source; build.rs regenerates the ignored
src/version.rs from it. Cargo.lock's root entry and Flutter's visible version
match2.1.0. Flutter's internal build number advances68→69 for platforms requiring
a monotonically increasing build counter; the product/deb version is2.1.0.
RPM, Arch and AppImage version fields are updated, but this release
still supplies only the tested Ubuntu26.04 x86_64 Linux artifacts. The inherited
legacy CI workflows remain unchanged: the publishing account lacks workflow-edit
scope, and this verified local build path does not use their VERSION variables.

The SX packaging script now requires the package version to match Cargo.toml
and the built executable's exact `--version` output. It rejects the old suffix
argument and stale binaries instead of publishing mismatched metadata.

## Build / package

```bash
RUSTDESK_DEV_DRM=1 RUSTDESK_DEV_HWCODEC=1 RUSTDESK_DEV_BUILD_MODE=release RUSTDESK_BUILD_JOBS=2 res/dev/build_linux.sh
python3 res/dev/package_linux_release.py \
  --version 2.1.0 --output /home/x/.cache/rustdesk-dev/releases/v2.1.0 \
  --flutter-root /home/x/flutter --unattended \
  --drmtap-source /home/x/.cache/rustdesk-dev/libdrmtap-wake \
  --drmtap-library /home/x/.cache/rustdesk-dev/libdrmtap-wake/build/libdrmtap.so.0.5.8
```

Commit source and ensure a clean worktree before packaging. libdrmtap remains
at the build.py pin, EGL enabled and independent privileged helper disabled.
The package includes its license, fixed root-library path, opt-in systemd
templates, BUILD-INFO, Chinese instructions and SHA256SUMS. Source URL and exact
core/library hashes in BUILD-INFO identify this build; version/build date changes
mean the core hash need not equal the earlier1.5.0 release.

Release checks: full Release build, exact2.1.0 executable/package/Flutter version
agreement, rejection of old-suffix packaging, `dpkg --compare-versions` upgrade
ordering, ELF dependency resolution, both extracted package entry points,
root-owned/read-only Debian payload, apt simulation, and remote asset hashes.
Post-install reconnect checks are separate from the previous full wake/lock
test. Do not label this version-only update a new full regression certification.

## Installation / existing functionality

Use `sudo apt install ./rustdesk-sx_2.1.0_amd64.deb`. Existing SX user data and the
OMEN99 systemd override remain; restart the service to load the replaced core.
See [activation and rollback](2026-10-26-unattended-linux-preview.md) for fresh
service setup. A client GUI already running uses the old mapped binary until
reopened. The application reports2.1.0 after restarting it.

Previously verified functionality includes screen-off wake, visible lock screen,
owner-entered OS password, and reconnect/service restart recovery. See
[actual previous package installation](../incidents/2026-10-26-release-package-install-omen.md).
This release does not change those implementations. Ubuntu24.04, logged-out
GDM, whole-machine reboot, suspend/resume, other architectures and sustained4K60
remain outside certification. Public packages still use system GTK.

## Rollback / regression surface

The old release assets remain available. Downgrade to the previously downloaded
`rustdesk-sx_1.5.0+sx.20261026.1_amd64.deb` with explicit apt `--allow-downgrades`,
restart OMEN's same service, and reopen the local GUI. No configuration rollback
or restoration of old Portal tokens is required. Root-only deployment backups
from the previous task remain available.

Runtime code is unchanged. Modified existing paths are product/build version
metadata, package version validation and publication documentation. The exact
CLI-version check is required to prevent shipping a renamed archive containing
the old1.5.0 binary. Other platform version fields are metadata synchronization,
not claims that those targets were built or tested.
